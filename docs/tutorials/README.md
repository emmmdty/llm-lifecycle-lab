## 写作规范

> 以下为教程撰写约定，每篇教程必须遵守。

### 结构与命名

- 目录：`docs/tutorials/`，图片放 `docs/tutorials/images/`。
- 文件名：中文编号命名，如 `01_数据下载与准备.md`，每阶段一篇。
- 每篇开头给出"学习目标"与"前置要求"；结尾给出"本章产出"与下一篇预告。
- 正文采用章节编号（1. / 2.1 / 2.2 …），风格参考 [happy-llm](https://github.com/datawhalechina/happy-llm)：目标先行、表格概览、代码块实例、结尾 FAQ。

### 图文规范

- 简单流程（线性步骤、分支判断）：使用 Mermaid 代码块（GitHub 原生渲染）。
- 复杂框图/结构图/关系图：使用 TikZ 绘制，导出 PNG 插入。
  - 源文件保留在 `images/`（`*.tex`），PNG 一并提交，保证可修改。
  - 编译命令：`xelatex -interaction=nonstopmode -halt-on-error 图.tex && pdftoppm -png -r 200 图.pdf 图`
  - 中文字体：`\usepackage[fontset=none]{ctex}` + `\setCJKmainfont{Noto Serif CJK SC}`。

### 内容边界

- **面向小白**：读者是初学者。专业术语（venv、BF16、compute capability、manifest 等）首次出现必须用一句话解释，最好用比喻或表格；命令要逐条解释含义，不能只贴代码。
- **不写个人网络因素**（cpolar 隧道、端口更新等）。
- **不暴露个人服务器信息**（用户名、域名、路径），不写本地↔服务器同步说明；默认读者直接在有 GPU 的服务器上使用本项目。
- 服务器硬件可以写（如"单卡 RTX 5090，32GB，支持 4090 等多卡"）。
- 环境必须写清楚：Python 版本、uv、CUDA、各环境 torch 版本及隔离原因（包括各工具链对 torch 的约束差异）。
- 每个阶段遇到的真实问题与解决过程，以"遇到的问题"小节写入教程。

### 流程

1. 阶段验收通过后，撰写该阶段教程；
2. 教程随阶段代码一起提交，图片与 `.tex` 源文件同时入仓；
3. 更新本目录（README）的状态表。
